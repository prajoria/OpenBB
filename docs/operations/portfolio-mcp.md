# Portfolio MCP operator runbook

This runbook starts, verifies, maintains, restarts, and rolls back the Portfolio
MCP stack without reading personal portfolio rows. Commands are PowerShell 7
commands run from the repository root unless stated otherwise.

The authoritative machine views are:

- `openbb_platform/extensions/mcp_server/openbb_mcp_server/assets/runtime_profiles.json`
  for installation and source provenance;
- `openbb_platform/extensions/mcp_server/openbb_mcp_server/assets/capability_policy.json`
  for reviewed exposure;
- `resource://openbb/capabilities/v1` for the connected Platform session; and
- the metadata-only inventory generated by `scripts/audit_mcp_capabilities.py`.

Client configuration is not evidence that a server, provider, browser bridge,
or worker is live.

## 1. Choose an access profile

| Profile | Intended use | Private network auth | Maintenance |
| --- | --- | --- | --- |
| `platform-standard` | Core reviewed provider and compute tools | Optional unless deployment policy requires it | Unavailable |
| `portfolio-read` | Sanitized Portfolio, Intelligence, cache-observability, and analytical reads | Required for HTTP | Unavailable |
| `portfolio-ops` | Read surface plus reviewed operator actions | Required for HTTP | Disabled until explicitly enabled |

`portfolio-ops` does not imply unrestricted mutation. Cache maintenance is
limited to five allowlisted durable job tools. Execution/broker mutations, raw
private portfolio rows, arbitrary jobs, SQL, scripts, invalidation, and MCP job
cancellation remain unavailable.

## 2. Clean checkout and source provenance

Initialize the Workspace submodule before using the dual launcher:

```powershell
git submodule update --init third_party\workspace
```

Portfolio profiles must run from the Portfolio checkout's Python environment.
Do not combine a Python executable from one checkout with source from another.
Create and build the checkout-local environment:

```powershell
$Repo = (Get-Location).Path
$PortfolioPython = Join-Path $Repo ".venv_portfolio\Scripts\python.exe"
py -3.12 -m venv .venv_portfolio
& $PortfolioPython -m pip install --upgrade pip
& $PortfolioPython -m pip install `
    -e .\openbb_platform\core `
    -e .\openbb_platform\extensions\platform_api `
    -e .\openbb_platform\extensions\mcp_server `
    -e .\openbb_platform\extensions\portfolio `
    -e .\openbb_platform\extensions\backtest `
    -e .\openbb_platform\extensions\regime `
    -e .\openbb_platform\providers\fmp `
    -e .\openbb_platform\providers\fmp_cached `
    -e .\openbb_platform\providers\yfinance `
    -e .\openbb_platform\tools\portfolio_utils
& $PortfolioPython .\scripts\pi_install.py
& $PortfolioPython -c "import openbb; openbb.build()"
$env:OPENBB_PORTFOLIO_PYTHON = $PortfolioPython
```

`pi_install.py` preserves editable installations for the coupled Portfolio
Intelligence and Techtrade packages. The remaining commands install every
checkout-local package required by `portfolio-read`; Portfolio Utils also
prepares the same environment for `portfolio-ops`. Optional FinancialToolkit
tools require a separate editable install of
`openbb_platform\extensions\financialtoolkit` and its underlying package.

The launcher runs `scripts/verify_mcp_runtime.py` before binding a port. It
checks required distributions, modules, source origins, profile policy, and app
target against `runtime_profiles.json`. The sanitized resolution artifact is
written outside the checkout under:

```text
%LOCALAPPDATA%\OpenBB\mcp-stack\runtime-resolution.json
```

Missing or wrong-origin packages are startup failures. Rebuild the selected
environment from checkout-local projects listed by the runtime profile; do not
mask provenance failures by adding an unrelated editable checkout to
`PYTHONPATH`.

## 3. Credential prerequisites

For `portfolio-read` and `portfolio-ops` over HTTP:

1. inject `OPENBB_MCP_SERVER_AUTH` from an operator secret store as a JSON
   `[username,password]` array;
2. require nonblank values; and
3. use a password of at least 32 characters for the launcher/operator profile.

Never place credentials in `.mcp.json`, command history, documentation,
readiness artifacts, or Git. Verify only that the secret is present:

```powershell
if (-not $env:OPENBB_MCP_SERVER_AUTH) {
    throw "Inject OPENBB_MCP_SERVER_AUTH from the operator secret store."
}
```

Provider and cache-database credentials belong in the normal OpenBB credential
store or deployment secret provider. Upstream API entitlement and quota rules
still apply to `fmp_cached`; a cached-provider registration is not a promise of
free or unmetered data.

## 4. Start and inspect the stack

Show launcher help and resolved parameters:

```powershell
Get-Help .\scripts\start-dual-mcp.ps1 -Detailed
```

Start the read profile:

```powershell
.\scripts\start-dual-mcp.ps1 `
    -Profile portfolio-read `
    -PortfolioPython $PortfolioPython `
    -PortfolioRoot $Repo
```

The launcher starts separate processes:

- Platform MCP: `http://127.0.0.1:8001/mcp`;
- optional standalone Workspace MCP:
  `http://127.0.0.1:8787/mcp`; and
- Workspace health: `http://127.0.0.1:8787/health`.

The Workspace backend also provides an integrated endpoint at
`http://127.0.0.1:8000/mcp`. Use either integrated `8000` or standalone `8787`
for one client session, not both as independent capability coverage.

Inspect only launcher-owned identities:

```powershell
.\scripts\start-dual-mcp.ps1 -Action Status
```

State and logs are outside the repository under
`%LOCALAPPDATA%\OpenBB\mcp-stack`. Status validates PID, process start time, and
executable identity and separately reports whether the recorded port listens.

## 5. Activate the Workspace browser bridge

Starting the Workspace MCP transport does not create a browser session.

The pinned Workspace UI supports bridge activation through the integrated
backend on port `8000`:

1. start the Workspace backend and open its UI;
2. authenticate to Workspace when required;
3. connect the MCP client to `http://127.0.0.1:8000/mcp`; and
4. wait for the UI-created bridge WebSocket session before calling browser,
   dashboard, widget, app, or agent tools.

The optional `8787` sidecar exposes `/bridge/session/start` and `/bridge/ws`,
but this repository does not ship a browser client that attaches the pinned UI
to those standalone routes. Use `8787` only with a separately implemented
bridge client that starts a session, retains the returned token, and connects
the browser WebSocket. Otherwise its browser-dependent tools must remain
unavailable.

A healthy `/health` response proves only the sidecar process is reachable.
Until the browser connects, Workspace tools must report browser unavailable;
they must not return success-shaped empty dashboard or widget data.

## 6. Metadata-only readiness

Generate a deterministic inventory outside the repository. This imports route
and registration metadata but does not call providers, services, transports,
cache tables, personal data, or browser sessions:

```powershell
$AuditDir = Join-Path ([System.IO.Path]::GetTempPath()) "openbb-mcp-audit"
Remove-Item -LiteralPath $AuditDir -Recurse -Force -ErrorAction SilentlyContinue
& $PortfolioPython .\scripts\audit_mcp_capabilities.py `
    --profile portfolio-read `
    --output-dir $AuditDir `
    --metadata-only
```

Expected outputs are `inventory.json`, `capabilities.csv`, and
`provider-models.csv`. The command prints a JSON summary with
`"metadata_only": true`, denominators, collisions, unavailable components,
scope limitations, and lineage state.

During startup, the launcher automatically runs its readiness script with the
injected authentication. The script validates MCP initialization, discovery,
required categories, prompt names, provider schema choices, adapter presence,
and denied-tool absence. Portfolio profiles require both cache-observability
tools. When maintenance is explicitly enabled, `portfolio-ops` additionally
requires all five cache-job tools; without opt-in those tools must be absent.
The readiness script does not call financial data or enqueue tools.

The script can be replayed without credentials against a standard-profile
server:

```powershell
.\scripts\test_portfolio_mcp.ps1 `
    -Profile platform-standard `
    -Uri http://127.0.0.1:8001/mcp
```

For authenticated Portfolio profiles, use the launcher's startup replay so it
constructs the authorization header from the injected secret. Do not paste an
authorization value into saved scripts or command history.

Read `resource://openbb/capabilities/v1` from the connected MCP session for the
single cross-surface view. `available`, `disabled`, `absent`, `not_evaluated`,
and `not_probed` are distinct states. Workspace, Agents, Daytrade, and fixed
HTTP examples remain `not_probed` until checked in their own sessions.

## 7. Enable guarded maintenance

Read [MCP cache-job operator runbook](./mcp-cache-jobs.md) before enabling
maintenance. Then:

```powershell
$env:OPENBB_MCP_ENABLE_MAINTENANCE_OPERATIONS = "true"
.\scripts\start-dual-mcp.ps1 `
    -Profile portfolio-ops `
    -PortfolioPython $PortfolioPython `
    -PortfolioRoot $Repo
```

Run the durable jobs worker as a separate supervised process. MCP handlers only
enqueue work and return run IDs. Use the allowlisted definitions/health/run
tools before enqueueing and retain run IDs for restart recovery.

Do not enable maintenance merely to inspect freshness. `cache_health` and
`cache_coverage` are sanitized aggregate read tools available to Portfolio
profiles.

## 8. Controlled restart after source changes

Never overwrite a running process and assume it reloaded source. Stop the
recorded stack, verify it is gone, then start from the selected checkout:

```powershell
.\scripts\start-dual-mcp.ps1 -Action Status
.\scripts\start-dual-mcp.ps1 -Action Stop
.\scripts\start-dual-mcp.ps1 -Action Status
.\scripts\start-dual-mcp.ps1 `
    -Profile portfolio-read `
    -PortfolioPython $PortfolioPython `
    -PortfolioRoot $Repo
```

`Stop` reads `processes.json`, verifies each exact identity, and stops only that
PID and its descendants. A stale or reused PID is skipped. Do not replace this
flow with name-based process termination.

If startup or readiness fails, the launcher rolls back the partial stack using
the same exact identities and removes partial state. Review the recorded error
logs before retrying.

## 9. Roll back to a known-good revision

Record the known-good Portfolio SHA before an update:

```powershell
git fetch origin portfolio
$KnownGood = git rev-parse origin/portfolio
```

To roll back without rewriting the active checkout or branch tracking:

```powershell
.\scripts\start-dual-mcp.ps1 -Action Stop
$RollbackRoot = Join-Path (Split-Path $Repo -Parent) "OpenBB-rollback"
git worktree add --detach $RollbackRoot $KnownGood
git -C $RollbackRoot submodule update --init third_party\workspace
$RollbackPython = $env:OPENBB_ROLLBACK_PYTHON
if (-not $RollbackPython) {
    throw "Set OPENBB_ROLLBACK_PYTHON to the rollback checkout's Python executable."
}
& (Join-Path $RollbackRoot "scripts\start-dual-mcp.ps1") `
    -Profile portfolio-read `
    -PortfolioPython $RollbackPython `
    -PortfolioRoot $RollbackRoot
```

The Python environment must belong to the rollback checkout. After recovery,
stop the rollback stack and remove only the named rollback worktree:

```powershell
& (Join-Path $RollbackRoot "scripts\start-dual-mcp.ps1") -Action Stop
git worktree remove $RollbackRoot
```

## 10. Troubleshooting

### Missing package or wrong source

**Signal:** runtime provenance verification fails before startup.

**Action:** inspect `runtime-resolution.json`; compare the missing distribution,
module, or normalized source with `runtime_profiles.json`. Install/rebuild from
the listed checkout-local project. Do not suppress the verifier.

### Missing provider

**Signal:** metadata inventory reports an unavailable component, or readiness
cannot find the required provider enum.

**Action:** install the provider in the selected environment, run the normal
OpenBB extension build, rerun metadata-only inventory, and restart. Do not
substitute an unrelated provider silently.

### Unreachable route or MCP transport

**Signal:** readiness reports transport unavailable or the recorded port is not
listening.

**Action:** run launcher `Status`, inspect the exact Platform error log, verify
the configured loopback port is free, and restart through the launcher. A
static `.mcp.json` entry is not reachability evidence.

### Workspace browser unavailable

**Signal:** sidecar health is reachable but browser-dependent tools report
unavailable.

**Action:** open/authenticate the Workspace UI, confirm it targets the selected
integrated or standalone endpoint, and reconnect the bridge. Do not restart
Platform or treat an empty result as success.

### Authentication denied

**Signal:** initialization returns HTTP 401/403 or readiness says
authentication rejected.

**Action:** verify the secret provider emitted a valid nonblank JSON pair,
restart so the server receives it, and let the launcher construct the header.
Never print the credential; readiness diagnostics redact credential-shaped
values.

### Cache database unavailable or permission denied

**Signal:** `cache_health` reports `unavailable` or `permission_denied`.

**Action:** verify database host reachability and least-privilege credentials
outside logs, then restart. Do not enqueue maintenance, issue raw SQL, expose
connection strings, or interpret the failure as an empty/fresh cache.

### Worker absent or queued run does not advance

**Signal:** cache-job health reports no worker, while the durable run remains
queued.

**Action:** start the separately supervised worker and query the existing run
ID. Do not re-enqueue without the same bounded idempotency key and do not claim
the MCP request executed the job.

## 11. Portfolio branch and pull-request direction

All integration pull requests target `portfolio` in `prajoria/OpenBB`. Start
from the fetched integration ref in an isolated worktree:

```powershell
git fetch origin portfolio
git worktree add -b <feature-branch> <worktree-path> origin/portfolio
```

Push the explicit feature ref without changing any existing upstream tracking:

```powershell
git push origin HEAD:refs/heads/<feature-branch>
gh pr create `
    --repo prajoria/OpenBB `
    --base portfolio `
    --head <feature-branch>
```

Do not retarget the local integration branch, change its upstream, force-push
`portfolio`, or open the PR against upstream OpenBB.
